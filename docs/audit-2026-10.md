# Security audit of 2026-10-19: findings and what was done

An external audit of commit `2d1454c` (static analysis, vulnerability scans, fuzzing, proof-of-concept tests) found ten items. Status after the fixes (tests named in brackets; "residual" is what the fix does not cover):

| ID | Finding | Status |
|---|---|---|
| HSM-01 | Go 1.26.0 toolchain with known stdlib vulnerabilities (TLS, HTTP/2) | **Fixed**: `go 1.26.9` in `go.mod`, the Dockerfile and the pipeline use `golang:1.26.9-bookworm` (digest-pinned in the Dockerfile); `govulncheck` is pinned and runs in the pipeline. Residual: the floating dependency set is Renovate's job; one open advisory in `x/crypto` is in code that is not called |
| HSM-02 | A successful answer was sent although the audit line could not be written | **Fixed**: the line is written before the answer; a failed write gives 503 and no plaintext (`TestFirstFailedAuditWriteWithholdsThePlaintext`). `unlock` needs the log too (`TestUnlockNeedsTheAuditLog`). Residual: the token may have done the operation before the line failed; no fsync or off-host delivery |
| HSM-03 | A rejected reload already changed the live token's key map; config, policy and identities were swapped in separate steps | **Fixed**: a generation (config, tokens as views with their own label map, policy, identification, TLS) is prepared and checked first and published at once; a refused reload changes nothing (`TestRefusedReloadChangesNothing`, `TestViewsShareTheSessionButNotTheKeys`). `module`, `token_label`, `token_serial`, `listen`, `admin_socket`, `audit.file`, `limits`, `transit.mount` now refuse a reload ("restart"). Rate counters are shared by all generations |
| HSM-04 | Replacing the client CA did not end access on open connections | **Fixed**: the chain (and its validity) is verified at every request against the current CA (`TestReplacedCAEndsAnOpenConnection`). Residual: no CRL/OCSP; revoking one certificate of a still trusted CA means removing the client from the policy |
| HSM-05 | Duplicate client names mixed grants; dangerous values were not validated | **Fixed**: duplicate clients, tokens and identities, several identity fields, bad sha256, negative or huge limits, empty `allow` entries, bad `max_bytes`, empty or non-hex CKA_ID, bad fingerprints are refused (`TestAmbiguityIsRefused`). Context is still limited per key, not per client: give tenants their own key if they must be isolated from each other |
| HSM-06 | Key information outside any budget; no bound on the queue to the token | **Fixed**: key information has its own budget; `limits.max_concurrent` (default 8) and `limits.queue_seconds` (default 2) bound the operations that wait for a token, a waiter gets 503 with `Retry-After` and gives up when its client does (`TestKeyInfoHasABudgetAndConcurrencyIsBounded`). Residual: a PKCS#11 call that hangs in the driver cannot be cancelled; counters are in memory and fixed-window |
| HSM-07 | `max_bytes` not applied on decrypt; trailing data after the JSON was cut off silently | **Fixed**: ciphertext length and decrypted size are checked; the body is read with a hard limit (413) and anything after the JSON value is refused (`TestSizeLimits`) |
| HSM-08 | Replicas and sessions: read errors skipped, public-key cache never cleared, removed tokens never closed | **Mostly fixed**: a version can be pinned by `fingerprint` (checked at load and at every use); the cache is dropped with each new session (`TestPointsAreReadAgainInANewSession`); removed tokens are logged out after the requests in flight are done; a token opened by a failed start or reload is closed; a derived object that cannot be destroyed drops the session. Residual: a late replica that holds the right key is accepted, one that holds another is refused only at use; PIN and secrets in Go memory are not fully wiped |
| HSM-09 | Container and supply chain: no memory limit, floating images and tools, no `.dockerignore` | **Fixed for what exists**: Kubernetes support was removed (a card ties the service to one machine; see "Running in Docker" in operations.md); the compose example has memory and process limits, read-only root, no capabilities; base images are pinned by digest; `.dockerignore`, `HEALTHCHECK` (`hsmgate ping`), pinned `govulncheck`. The GitHub Actions and GoReleaser files are gone (Woodpecker). Residual: no signed releases or SBOM |
| HSM-10 | Admin HTTP without timeouts; secret files checked by path (TOCTOU) | **Fixed**: timeouts on the admin server; the socket is created with mode 0600 whatever the umask; key and PIN files are opened once with `O_NOFOLLOW` and judged by descriptor (regular file, owner, mode, size) (`TestSecretFileIsReadFromTheDescriptor`) |

Not covered by the fixes, as the auditor noted: timing and side channels, a hung driver, root on the host, hardware tests (unplug, another card with the same label, a late replica, DKEK recovery), an independent review of the cryptography. The Russian report with the raw tool output is not part of the repository (it holds local paths of the audit machine).
